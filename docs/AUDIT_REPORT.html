What the audit did to WHISPER-CBPF

Whisper fits candidate physical models to a transient light curve and tells you which one the data prefers. This is a plain-English account of a two-day audit: what was broken, what was measured, and what a new user can now actually do.

16 commits 41 files · +17,196 / −228 253 CPU tests passing now public on GitHub

The one-sentence version

Whisper's science was sound, but a working astronomer couldn't reach it — every GPU fit demanded that you hand-write the mathematics yourself, several published numbers were wrong, and the package couldn't be installed at all. The first two are fixed and measured. The third was fixed by pushing the repository, which happened while this report was being written.

The goal we tested against

Not "do the tests pass". The bar was: load a real light curve — AT2017GFO, the kilonova from the first neutron-star merger — fit a tidal disruption event, a supernova, and one- and two-component kilonovae to it; on processor and on graphics card; in brightness units and in magnitudes; with every sampler that can legitimately run each combination; and get back scores you can defend.

That is now a script you can run: scripts/compare_at2017gfo.py. Combinations that cannot work print the reason instead of quietly vanishing from the table.

What was actually wrong

1. The graphics-card samplers were unreachable

Whisper had slots for a fast, differentiable version of each model — and nothing read them. So every GPU fit required the user to hand-build the probability mathematics before the sampler would accept it. Asking for one the obvious way produced a bare Python error about a missing argument.

Before

Five GPU samplers, each needing a hand-written density or forward model. No worked example in the docs.

Now

wp.fit(lc, "kilonova_one_jax", sampler="nuts_gpu") just works. The two independent NUTS implementations agree to four significant figures, which is the cross-check they exist to provide.

2. Magnitude space was silently ignored

Astronomers work in magnitudes. Three samplers accepted a "which units?" setting, recorded it in the output, and then never used it — so magnitude data was scored in brightness units regardless of what you asked for. It now works, and the result records whether the setting was honoured or merely noted.

3. Six places returned a plausible wrong number with no error

These are the dangerous kind: no crash, no warning, just a number you'd have believed.

  • A brightness-to-magnitude floor that didn't floor — it returned infinity in single precision, which is the mode that sampler runs in by default.
  • An outlier-tolerant likelihood that reported its goodness-of-fit score computed under a different likelihood than the one it fitted with.
  • Eleven copies of the same brightness-to-magnitude conversion, one of which disagreed with the rest by 19 magnitudes.
  • A fit on an empty light curve completed and reported a score. Cause: filtering by date before setting the explosion date silently discards every row.
  • One sampler was fitting a flat prior where its documented twin used the real one — they only agree if every prior is uniform, and Whisper's kilonova has one that isn't.
  • The WAIC score never said when it was meaningless.

4. Documented facts that weren't

Four documents said

Registering a supernova model refuses immediately in single precision, so the model never enters the registry.

Measured

All 12 of 12 supernovae register successfully and appear in the registry. The refusal happens later, at the first prediction. A registry entry was never evidence the session could run it.

Also corrected: a tutorial listing 3 models where there are 6 and 4 samplers where there are 13; a reference contradicting itself on the test count; roughly 25 documentation links pointing into folders that have never existed in this repository.

What we added

Nested sampling — the evidence sampler

Every other sampler ranks models with an information criterion. Nested sampling computes the evidence directly, which is what a Bayes factor is made of. It's built on Whisper's existing prior machinery, so it needed no new mathematics.

Verified against a problem with a known answer: the computed evidence landed 0.71 standard deviations from the analytic value, and the posterior width matched theory to within 2%.

Worth knowing

Evidence depends on how wide you made your priors, in a way information criteria do not. Widening one prior by 100× moved the evidence by −4.1 nats (theory says −4.61) while barely moving AIC. Only compare models whose priors you'd defend before seeing the data.

The crossover claim was unqualified, not wrong

The docs said the graphics card "crosses over at roughly 50,000 simulations", with no measurement anywhere behind it. Measured, the answer moves by a factor of 60 depending on two things that sentence never stated — whether you pay the compilation cost each run, and whether your processor baseline uses all its cores.

Checking our own work

Everything above was re-checked by an independent adversarial pass whose only job was to disprove it. Of 45 claims: 30 survived, 5 were refuted and 10 were partly wrong. It also found 8 defects in code written during this same audit — including one that corrupted a cache so badly it broke plotting, and one where a fix for a slowness trap made that sampler 49× slower.

The honest read

Finding eight defects in two-day-old, carefully-written code says something about the rest of the package. That error rate is the strongest argument for treating any single number here as provisional until it has been re-measured.

Installing it

The repository is now public, so this works today:

pip install "git+https://github.com/phelipedarc/WHISPER-CBPF.git"

That gives you a complete processor-only toolkit: data loading, plotting, the analytic models, and the abc, abc_smc, mcmc and nested samplers. Nothing on PyPI yet, so the whisper-cbpf name won't resolve.

Add-onGives you

[models]redback — the redback kilonova, and the priors read from its files

For everything:

pip install "git+https://github.com/phelipedarc/WHISPER-CBPF.git#egg=whisper-cbpf[gpu,models,pymc,sbi]"
Graphics cards: read this or lose 50× silently

JAX decides whether it can see your card when Python starts. Get the library paths wrong and it quietly falls back to the processor — correct answers, roughly 50× slower, no error message. You must source the environment script before starting Python, and then confirm.

source scripts/whisper-gpu-env.sh     # BEFORE python starts
python -c "import whisper_cbpf as wp; ok, msg = wp.check_gpu(); print(ok or msg)"

That script currently only exists in a source checkout — it is not included when pip installs the package, which is the next thing being fixed. Until then, clone the repository if you need the graphics card.

Check the whole thing end to end:

python scripts/compare_at2017gfo.py --device cpu --space both --quick

Is it ready for the astronomy community?

Nearly. Yesterday the answer was a flat no, because nobody could install it. That's resolved. What remains:

  • The graphics-card setup script isn't shipped with the package. Without it, JAX silently runs on the processor — and a beginner will never know.
  • The TDE and supernova rows of the readiness matrix are reasoned, not run. Their model calculations are verified to machine precision, but the full sampler sweeps didn't complete. They are labelled as the weakest evidence in the report rather than presented as verified.
  • WAIC is frequently unusable on real fits. It's flagged now, and the usual cause is one stuck chain rather than a bad model — but it means one of the three headline scores often can't be quoted.
  • No automated testing on graphics hardware. The entire GPU half is checked by hand.

Fair summary: ready for a collaborator who can clone the repository and ask questions. Not yet ready for a stranger who will install it and trust the first number it prints.
